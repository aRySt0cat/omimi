# このディレクトリについて (AI エージェント向け)

Omi (身につける常時録音デバイス) で録った **個人の会話記録** です。
自宅サーバ (omi-home-server) が自動で作成・更新します。

## 取り扱いの注意

- 個人や周囲の人の会話を含みます。**外部のサービス・Web 検索・共有リンクに内容を送らないでください。**
- このディレクトリ内のファイルは **読み取り専用** として扱ってください。サーバが上書きします。
  - **書いてよいのは `notes/` の中だけ** です。分析結果や整形したデータはここに置いてください。

## 読む順番

1. `timeline/YYYY-MM-DD.md`: その日の会話を時系列に並べたもの。まずこれを読む。
2. `timeline/YYYY-MM-DD.jsonl`: 同じ内容の構造化データ。集計や抽出に使う。
3. `vocabulary.md` (あれば): 用語集。人名・専門用語の正しい表記・読み・よく間違う表記・説明。まとめではこの表記を使う。
4. `audio/YYYY/MM/DD/<segment_id>.json`: 録音 1 件ごとの詳細 (端末・サーバ両方の文字起こし、話者分離の区間)。
5. `audio/YYYY/MM/DD/<segment_id>.opus`: 音声 (Ogg Opus, 16 kHz モノラル)。

`omi.sqlite3` (全データの DB)、`models/`、`token`、`chatgpt/` は読まなくてよいです。`token` と `chatgpt/` は秘密情報なので、開かないでください。

## 用語

| 用語 | 意味 |
|---|---|
| セグメント | 録音の 1 単位。次のどれかで区切られる: 話し終えて 30 秒無音 / 最大 5 分 / ボタンの「区切り」 |
| 話者 | 声で識別した人。名前はユーザが付ける (`自分` = 装着者本人)。大事な人にだけ名前を付けるので、名前のない人 (店員・駅や電車のアナウンス・通りすがりなど) はすべて `その他`。`その他` でも同じ声は同じ `speaker_id`。話者が分からない短い発話は `null`。名前は後から変わることがあるので、同一人物の判定には `speaker_id` を使う |
| 言語 | 発話ごとの言語 (`ja` / `en`)。自動判別 |
| 印 (marker) | 装着者が Omi のボタンで付けた印。下の表を参照 |

### 印の意味

| kind | 表示 | 操作 | 意味と扱い方 |
|---|---|---|---|
| `highlight` | ⭐ 注目 | 1 回押し | **直前〜直後の会話が大事**。要約では必ず触れる。前後 1〜2 分を重点的に読む |
| `split` | ✂️ 区切り | 2 回押し | **話題・場面の切れ目**。会話をまとまりに分けるときの境界として使う |
| `memo` | 📝 メモ | 長押し | **この後に本人が話す内容は、自分へのメモや指示** (TODO・覚え書き・エージェントへの依頼)。次の区切りか、話し手が変わるまでを 1 つのメモとして扱う |

## timeline/YYYY-MM-DD.jsonl の形式

1 行 1 レコード。時刻順。時刻は ISO 8601 (タイムゾーン付き)。`type` で種類を区別します。

```jsonc
{"type": "segment", "id": "20261010T040826Z-26437f3d", "start": "...", "end": "...", "duration_s": 21.0,
 "has_speech": true, "speakers": ["自分", "Daniel"], "audio": "audio/2026/10/10/<id>.opus",
 "transcript_source": "server"}
{"type": "utterance", "segment_id": "...", "start": "...", "end": "...", "speaker": "自分", "speaker_id": 3,
 "language": "ja", "text": "おはようございます。", "source": "server"}
{"type": "marker", "id": "...", "kind": "highlight", "label": "注目", "at": "...", "segment_id": "..."}
```

| フィールド | 説明 |
|---|---|
| `has_speech` | 話し声があったか。`false` は物音だけの録音 (Markdown では省略)。`null` は処理中 |
| `transcript_source` / `source` | `server` = 自宅サーバの Whisper (話者ごとに区切って文字起こし。こちらを優先) / `device` = iPhone の Apple 音声認識 |
| `speaker` | 話者名。`null` は不明 (発話が短い等) |
| `segment_id` (marker) | 印を押した時刻を含む録音。録音外 (マイク休止中) に押した場合は `null` |

## 文字起こしの注意

- 自動の文字起こしなので誤りがあります。固有名詞・数字は特に誤りやすいです。
- 同じ録音に `server` と `device` の両方があることがあります。timeline には片方だけ載せています。もう片方は `audio/.../<id>.json` にあります。
- 話者の識別も誤ることがあります。会話の流れと矛盾する場合は、その旨を書き添えてください。

## notes/ (AI のまとめ) の決まり

`notes/` に書いた Markdown は、本人の iPhone (Omimi アプリの「まとめ」) と Web 画面に表示されます。

| ファイル | 中身 |
|---|---|
| `notes/YYYY-MM-DD.md` | その日のまとめ。その日の「記録」にも出る |
| `notes/todo.md` | 日をまたいで続くやること (`- [ ]` / `- [x]`) |
| `notes/<名前>.md`, `notes/<フォルダ>/<名前>.md` | そのほかのノート (人物・話題など)。2 階層まで |

- 最初の `# 見出し` が題名、その直後の `> 引用` (無ければ最初の段落) が一覧に出る要約になります。
- 会話を指すときは `[12:42](omimi://segment/<segment_id>)` と書くと、タップでその会話が開きます。
- 表示できるのは、見出し・段落・箇条書き (チェックボックス付きも可)・番号付きリスト・引用・表・コード・区切り線・**太字**・*斜体*・`コード`・リンクです。HTML は表示されません。
- ファイル名に使えるのは文字・数字・`-` `_` `.` と空白です。1 ファイル 1 MB まで。

夜の整理 (`omi-server nightly`) では、`prompts/nightly.md` の指示でこれらを書きます。

## 頼まれそうな作業の例

- **1 日の要約**: `timeline/<日付>.md` を読み、話題ごと (✂️ 区切り単位) に要約する。⭐ 注目の箇所は必ず含める。
- **TODO・メモの抽出**: 📝 メモの直後の本人の発話を抜き出し、TODO・覚え書き・依頼に分類する。
- **人物ごとの記録**: `speaker_id` ごとに発言をまとめる。
- **期間の検索**: 複数日の `*.jsonl` を読み、キーワード・話者・言語で絞り込む。
